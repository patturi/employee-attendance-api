# Code Review & Defect Log

## Defects Identified in Starter `app/main.py`

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `health()` | Does not check MongoDB connectivity; returns `{"status": "ok"}` unconditionally even when database is disconnected. | Stop MongoDB container; `GET /health` still returned 200 instead of 503 per OpenAPI contract. | Added `client.admin.command("ping")` within a `try/except` block, returning 503 if unreachable. |
| 2 | `create_employee()` | Duplicate employee check is a race condition (`find_one` then `insert_one`), and does not catch `DuplicateKeyError`. Also allows duplicate inserts concurrently. | Send two concurrent `POST /employees` requests with identical `emp_code`; both could insert duplicates without database unique index. | Created unique index on `emp_code` at startup, and wrapped `insert_one` to catch `DuplicateKeyError` and return 409. |
| 3 | `EmployeeCreate` schema | Missing validation for `emp_code` regex (`EMP\d{4,6}`), valid email address format, date format for `joined_on`, and rule that `shift_start != shift_end`. | POST employee with `emp_code: "123"` or invalid email `"notanemail"` or identical shift times succeeded with 201. | Added Pydantic field validators and regex patterns matching `openapi.yaml`. Raised 422 if `shift_start == shift_end`. |
| 4 | `create_employee()` | `created_at` was stored as naive datetime or string, and response serialization did not output integer epoch milliseconds. | Inspecting JSON response showed ISO datetime string or lacked millisecond epoch integer per data model contract. | Stored UTC datetime in MongoDB and serialized to integer epoch milliseconds truncated to whole seconds. |
| 5 | `list_employees()` | Pagination offset bug: `skip = page * page_size`. When `page=1`, skips 20 records, hiding page 1 completely. | Calling `GET /employees?page=1` returned an empty list or skipped the first 20 records. | Fixed formula to `skip = (page - 1) * page_size`. |
| 6 | `list_employees()` | `total` count did not apply the `department` filter; counted entire collection. Missing sort on `emp_code`. | Filter `GET /employees?department=Sales` returned `total` equal to total company headcount instead of department count. | Applied filter dictionary `q` to `count_documents(q)` and added `.sort("emp_code", ASCENDING)`. |
| 7 | `compute_late_minutes()` | Incorrect grace period comparison: `minutes > 10` checks only minute integer component rather than elapsed seconds > 600. | At 09:40:01 IST (10m 1s elapsed), `minutes` was 10, so it returned 0 late minutes instead of 10. | Changed logic to calculate `elapsed_seconds = (punch_in - shift_start).total_seconds()`, checking `if elapsed_seconds > 600: return int(elapsed_seconds // 60)`. |
| 8 | `compute_late_minutes()` | Did not account for the record's attendance date or timezone; assumed shift start was always today's local date. | Punch-in for an overnight shift or past/future date evaluated against server local time today. | Combined the specific `attendance_date` with `shift_start` in IST timezone. |
| 9 | `compute_work_hours()` | Used Python built-in `round(hours, 2)`, which implements banker's rounding (round half to even). | Value ending in `.x25` rounded down to `.x2` instead of rounding half-up to `.x3` required by R4. | Implemented `Decimal` rounding with `ROUND_HALF_UP` to 2 decimal places. |
| 10 | `compute_overtime()` | Missing the 30-minute minimum threshold (R3). Any positive minutes were returned as overtime. | Punch-out 10 minutes after shift end returned 10 overtime minutes instead of 0. | Added threshold check: return `whole_minutes if whole_minutes >= 30 else 0`. |
| 11 | `compute_overtime()` | Ignored overnight shifts where `shift_end <= shift_start`. Shift end was treated as same calendar day as punch-in. | Overnight shift 22:00–06:00 resulted in negative elapsed seconds and 0 overtime even when working past 06:30. | Added overnight shift detection: shift end falls on `attendance_date + 1 day`. |
| 12 | `punch_in()` | Did not truncate instants to whole seconds (R1). Allowed arbitrary milliseconds. | Sending epoch millisecond `1782878400123` stored sub-second data, violating contract. | Truncated epoch milliseconds via `(ms // 1000) * 1000`. |
| 13 | `punch_in()` | Did not enforce unique attendance record per employee per date (`emp_code`, `date`). Check-then-insert race condition. | Concurrent punch-ins created two records for the same employee on the same date. | Enforced compound unique index `{"emp_code": 1, "date": 1}` and caught `DuplicateKeyError` to return 409. |
| 14 | `punch_in()` | Returned MongoDB `_id` field in API response; returned raw BSON datetime objects instead of epoch milliseconds. | Response contained `{"_id": "...", "punch_in": "2026-07-01T..."}`, violating OpenAPI spec. | Added serialization helper removing `_id` and converting datetimes to epoch milliseconds. |
| 15 | `list_attendance()` | Loaded entire database query into Python RAM with `list(db.attendance_logs.find(q))` before slicing. | High memory consumption and severe slowdown on large datasets; potential out-of-memory crash. | Used native MongoDB `.skip(skip).limit(page_size)` with compound index sorting. |
| 16 | `list_attendance()` | Allowed invalid date range `date_from > date_to` without validation. | Query with `date_from=2026-07-10&date_to=2026-07-01` returned empty results with 200 instead of 422. | Added validation raising `HTTPException(422, "date_from cannot be greater than date_to")`. |
| 17 | `Missing Endpoints` | Starter code completely omitted 7 required endpoints: `POST /attendance/punch-out`, `PATCH /attendance/{emp_code}/{date}`, and all analytics/admin endpoints. | Client requests to punch-out, regularization, analytics, or explain returned 404. | Implemented all missing endpoints adhering strictly to OpenAPI schemas and MongoDB aggregation pipelines. |

## Examined and Decided NOT to be a Defect

1. **`punch_in` default status `PRESENT`**:
   - The starter defaults `status` to `PRESENT` when not provided in request body. We checked `openapi.yaml` and verified that `status` is optional with enum values `PRESENT`, `WFH`, `ON_DUTY` and default `PRESENT`. This is valid and expected.
2. **IST Timezone Offset +05:30**:
   - The specification mandates IST (UTC+05:30) for shift calculations and calendar dates regardless of the host server's local timezone. Using explicit `timezone(timedelta(hours=5, minutes=30))` rather than relying on system local time is required by R1 and is not a defect.
3. **Empty history array on initial punch-in**:
   - Initial attendance logs start with `history: []`. Some implementations store initial creation in history, but `DATA_MODEL.md` explicitly specifies `history` documents regularization audit history, and the OpenAPI schema shows `history` as an array of regularizations. Starting with `[]` is correct.
